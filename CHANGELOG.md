# Changelog

All notable changes to Agent Farm. Detailed release notes live in the built-in guide (`Agent Farm: Open Guide` → Release Notes / Sürüm Notları).

## 3.65.0 — The garbage characters came back, so this time a hook holds the line (2026-08-05)

**Every stray character in the command palette, the right-click rows, the sidebar tooltips, the settings descriptions, the walkthrough and the empty-view messages came from one file.** `package.json` had been read as CP1252 and written back as UTF-8 — 135 lines of collateral damage on a commit whose only intended change was `"version": "3.63.0"` → `"3.63.1"`. The repaired file is now byte-identical to the last undamaged copy apart from the version line, which is the proof that the repair neither missed anything nor over-corrected. Roughly half of it was invisible: CP1252's five undefined slots come through as bare C1 controls that render as nothing, which is why it survives review.

**This is the second time the same fix has been made, so it is no longer left to memory.** `test/test_encoding.js` already existed and already catches this; what was missing was anything that runs it. Two places now do: `.githooks/pre-commit` blocks the commit and prints the repair command, and `npm run package` refuses to build a VSIX over a damaged tree. The hook installs itself on `npm install` (the `prepare` script points `core.hooksPath` at `.githooks`), so a fresh clone is protected without a setup step.

## 3.63.1 — The step-glyph key, where you will actually look for it (2026-08-04)

The chips are one character each, and a glyph is only as good as the place you can re-learn it. Two keys, both hung on labels that are always on screen and never move: the Console puts it on the **session id** at the far left of the line under the composer (hover), and the session page puts it on the **Activity card** — the card that counts those very steps. Hover it for the whole scheme in words; **click it** to pin the strip open under the cards. Folded by default, because a legend you have already learned is clutter, and it stays open across re-renders once you open it.

The blueprint (EN + TR) gained the section this whole line of work was missing — *What Work Costs: two figures and nine kinds of step*: the frozen-data experiment, why the raw figure is the wrong unit, the cache-write TTL correction, the endpoint calibration, the nine step kinds with what each one costs, and the four settings that now control all of it.

## 3.63.0 — The weight table is a setting now, and the limit was measured against the real endpoint (2026-08-04)

**The ⚖ scheme is fully controllable from Settings.** These numbers are the provider's rate card, not ours; one of them moving should never need a release. Four settings, all under **Cost & budgets**: `quotaWeightMode` (`model-aware` · `model-flat` · `raw`), `quotaWeights` (the whole table — per model regex: input, output, 5-minute cache-write, 1-hour cache-write, cache-read, all relative to one Sonnet input token = 1), `quotaBrakeBasis` (which figure the quota guard and the model-downgrade rule read: whichever is further along · weighted only · raw only) and `windowWeightedTokenLimit`. Changing the table re-reads every transcript on the spot, because the ⚖ total is summed during the parse and a new rate with old arithmetic behind it would be worse than none. An unusable table — an empty array, a typo in a regex — falls back to the shipped one rather than quietly zeroing the gauge being watched.

**‼️ AND THE LIMIT WAS FINALLY MEASURED, NOT ARGUED ABOUT.** Utilization was sampled from the plan's own endpoint twice inside one window (both readings carried the same reset time, so they are the same window): **29% → 82% in 28.1 minutes over 96 API calls cost 38.13M raw**. That is 0.72M raw per percentage point — **a full 5-hour limit of ~72M raw tokens**, which is almost exactly the "it used to fill at 75M" that started this whole line of work. That recollection was right.

**Then the account changed, and the same measurement on a fresh window says something else entirely.** A new account opened at 0% and reached **42% on 3.15M raw** — an implied limit of **7.5M raw**, nearly ten times smaller. In WEIGHTED terms the same two windows imply 46.9M and 23.8M: the gap closes from 9.6x to 2.0x. So the unit is doing most of the work — the first window was 98.7% cache reads, the second 27.6% cache **writes**, and writes are the expensive part — but a 2x residual remains, and with two different accounts there is no way to tell whether that is the weighting or simply two different allowances. Settling it needs two samples of differently-shaped work inside ONE account, which the `usage.window` op now makes a one-line job.

## 3.62.0 — Every cache write was being under-charged, and every step now says what KIND of step it is (2026-08-04)

**‼️ A CORRECTION FIRST: 3.61.0's cache-write weight was wrong, on 100% of the data.** It was set from the published price ratio for a **5-minute** cache write (1.25x a fresh input token) without first checking what the transcripts actually contain. They contain the answer, in a field nobody had read: `usage.cache_creation` splits the write by TTL, and across 3 813 assistant lines in the 40 newest transcripts **17 923 938 of 17 923 938 cache-creation tokens were `ephemeral_1h` and zero were 5-minute**. A 1-hour write costs **2x** input, so every ⚖ figure was 1.6x light on the single most expensive thing in a turn. `toUsage()` now reads the split and prices each half at its own rate, everywhere — a usage block that reports no split is charged at the **1-hour** rate, because under-stating what a turn cost the limit is the exact failure this whole line of work exists to fix.

**Every step now says what KIND of step it is.** A turn was a list of things that looked alike: `Read D:/x.ts` and the model reasoning for nine seconds drew the same sort of row, though one runs on this machine for free and the other is billed at the output rate — so "where did my limit go?" had no answer on any page. Nine categories, each with one glyph and one sentence saying what it costs: **◈ thinking** · **▸ reply** · **⌘ local tool** · **⇄ MCP tool** · **⌗ web** · **⑂ sub-agent** · **⚙ harness** · **↩ tool result** · **· local only**. They are not invented — every one was counted in this machine's own transcripts first (60 files, 21 705 lines): Bash 1349, Edit 1086, Read 636, PowerShell 425, Grep 230, Write 168, `mcp__obsidian__*` 45, `mcp__playwright__*` 13, WebFetch 5, WebSearch 5, and the harness tools besides.

**‼️ Thinking was the invisible one.** 1 737 thinking blocks against 878 text blocks — the model reasons about twice as often as it speaks, every one of those tokens is billed at the **output** rate, the dearest there is, and nothing anywhere counted them. The rows are still not rendered (they are the model's private working) but the turn now says how many there were.

**And each step carries what its API call spent** — raw and ⚖ — written **once per call, on its first block**. One call carries several steps and repeats its whole usage on each of them, so a row with no figure did not cost nothing: it rode on the call above it, and the tooltip says exactly that. Live in the Console conversation, in the working strip (the spinner now leads with the category of what is happening), in the transcript page's meta line, and in the Markdown export.

*Also:* a browser driven over MCP (`mcp__playwright__*`, `mcp__chrome-devtools__*`) is filed as **web**, not MCP — it is traffic to the open internet whatever the server is called. A tool nobody has listed reads as **local**, which is the assumption that costs nothing when it is wrong. The webview's copy of the category table is held identical to `src/core/stepkind.ts` by `test_step_kinds.js`, so a chip in the Console and a cell in the viewer cannot describe one step two ways.

## 3.61.0 — Every token figure now carries what it cost the LIMIT, not just what it measured (2026-08-04)

Five investigations have now gone looking for a token-counting bug. There is not one, and this release settles it with the experiment nobody had run — then fixes the thing that actually misled everyone.

**The experiment: freeze the data, swap only the code.** Every earlier check either *read* the two builds' source and pronounced them the same, or compared two live sessions — which changes the code **and** the data at once and can therefore decide nothing. Instead, 3.56.0 (`6a4ea20`) and 3.60.1 (`HEAD`) were built in separate worktrees and their own `parseSessionFile` + `PricingEngine` were run over **the same 355 transcripts**. Result: **4 329 012 662 tokens and $8975.1433 from both**, zero sessions differing, per-turn arrays identical. The counting code is not the variable. The figures are also right in absolute terms — an independent parser sharing no code with the extension returned 6.866M / 6.856M / 10.759M for the three turns of the session under dispute, matching the page.

**‼️ THE REAL FAULT WAS THE UNIT.** A raw token total is 94-99% cache reads, and the plan's rolling limit charges a cache read at about a tenth of a fresh input token (and an output token at five, and Opus at five Sonnets). So the raw figure is dominated by the cheapest thing in it and **is not proportional to the wall it appears to describe**: measured across 32 days of this machine's transcripts, raw ÷ weighted for a peak 5-hour window ranges **0.80x to 3.86x**. The eight heaviest windows sit inside a **±13% band** by weighted total while spanning **111M-175M raw**. That is the whole of "the limit filled at 75M once and at 25M another time" — same wall, different shaped work, and a surface that printed only the raw number made it look like the counter had changed.

**So every token figure in the extension now carries both.** Raw first, then `⚖` and the weighted twin: Console cards, the live turn strip, the finished-turn line and the session line under the composer; the Sessions tables and their per-turn fold-outs; the Turns page; the session viewer's Tokens card, turn band, turn table and Markdown export; the Dashboard's agent tables, range card and 5h card; the Portfolio's 30-day columns and fleet row; the Live Timeline cards; the sidebar hovers; the status bar's lap chip and tooltip; and the fleet report's tables. One formatter, one tooltip, one definition (`QUOTA_WEIGHTS` in `pricing.ts`) — the weighted figure is summed off the **same lines, inside the same dedup guard, from the model that served each one**, so it can never tell a different story from the raw figure beside it. A sub-agent on haiku is weighed as haiku, not at its parent's rate.

**A ceiling you can actually brake on.** `agentFarm.windowWeightedTokenLimit` sets the 5-hour limit in weighted tokens; the quota guard and the model-downgrade rule then read the figure that tracks the plan instead of the one that tracks context size, and the Dashboard draws its bar from it. It defaults to 0 and **changes nothing until you set it** — the existing `windowTokenLimit` behaves exactly as before, and with both set the brake takes whichever is further along. New bridge op `usage.window` returns the window in both units plus the ratio between them.

**Honest about what it is:** the plan's exact formula is not published. These weights follow the published price ratios and are kept in their own table rather than off `agentFarm.pricing`, so correcting a billing rate cannot silently move the limit gauge. The ground truth for "how full am I" stays the Plan usage card.

## 3.60.1 — The garbage on the end of menu titles: one file, mis-decoded up to three times (2026-08-04)

Command palette entries, right-click rows and sidebar hovers had been carrying two or three junk characters glued to their ends — `Agent Farm: Delete Key`, `Set Secret`, every title that ends in an ellipsis. **All of it came from one file.** `package.json` had at some point been read as CP1252 and written back as UTF-8, which expands every non-ASCII character into two or three others; it happened more than once, so strings carry **two and in places three** layers of the same damage. **124 strings are repaired.**

**Why it looked random.** Only strings containing a non-ASCII character were touched, so `Open Dashboard` came through clean while `Set Secret…` did not — and what the eye read as "two odd characters at the end" was almost always the trailing `…`. The same accident ate `—` `·` `→` `×` `✓`, the emoji in the Insights welcome, and the word `Türkçe` in the guide-language setting.

**Half the damage was invisible.** CP1252 has five undefined slots (`0x81 0x8D 0x8F 0x90 0x9D`), and those bytes came through as bare C1 control characters — nothing on screen, a box in some fonts, and no way to find them by looking. That is why this was never spotted in a diff.

**A test now owns it, because the eye cannot.** `test/test_encoding.js` walks every `.json` `.ts` `.js` `.html` `.css` `.md` in the repo (303 files) and fails on any run that reverses cleanly to valid UTF-8, or on any C1 control at all. A run that does *not* reverse is not reported — Turkish prose produces lead+continuation pairs by accident (`aç…` is `ç` followed by an ellipsis) and those are not damage. `node test/test_encoding.js --fix` repairs in place and refuses to write JSON it just broke.

## 3.60.0 — A turn says how many calls, how long, and where it left the window (2026-08-04)

Two days were spent proving the token counter was not broken. It was not — four shipped builds (3.57.0 / 3.57.1 / 3.58.0 / 3.59.1) were unzipped and run over the same six transcripts, and all four returned the same figure to four decimal places, tokens, turns, cost, messages and tool calls alike. But the investigation only took two days because **the surfaces answered the wrong question about a turn**, and this release fixes that.

**‼️ One number was two questions.** A turn showed a count labelled `msgs` on the transcript page and `lines` on the Console strip; both meant *steps* — one reply fragment or one tool call. What the tokens actually follow is **API calls**, and a single call routinely carries several steps (measured over 35 610 assistant lines / 17 310 calls: **2.06 steps per call**). So a run that halved its round trips while its visible steps held looked unchanged, and the token total moving underneath it looked like a counting fault. Every surface now writes the pair: **`14api/26`** — calls first, steps second, one shared formatter, one shared tooltip. `steps` is the name everywhere; `msgs` and `lines` are gone.

**A turn row now says how long it ran and where it left the context window.** Both were already measured and neither was shown: the row could price a turn but not tell you it took forty minutes, and the only context figure on the page was the session's. `took` is the turn's own running time (prompt → last line), `ctx` is what the window held when it ended. On the Turns page these sit beside `Duration`, which is a *different* measurement — the gap to the next turn, including however long the ball sat with you — and each now says which it is in its tooltip.

**Durations are written the same way everywhere:** `34s` · `3m-29s` · `1h-4m-23s` · `1d-7h-54m-41s`. The strips counted seconds forever, so a turn that ran an hour said `3847s`. A unit appears only once it is reached, and from there down every unit is always written (`1h-0m-5s`, never `1h-5s`) so the string reads left to right without checking which fields happen to be present. The webview and node copies of the formatter are held identical by a test that runs both across every unit boundary — a Markdown export must not describe a turn differently from the table it came from.

*Also:* the Console strip's own dedup was found sound but resting on an assumption — it keeps one usage key, not a set, on the grounds that repeats are always consecutive. Measured across 18 300 repeats: zero exceptions, so it is correct today. It is on the backlog as a `#bug` anyway, because a measurement is not an invariant.

## 3.59.1 — What a turn's tokens are made of (2026-08-03)

A session that used to report ~77M tokens for an hour of work started reporting ~17M for an hour that felt the same, and 6.107/6.108 were the suspects. **They are not.** Nothing in the token path changed between 3.57.0 and 3.59.0 — `sessions.ts`, `sessionViewer.ts` and `pricing.ts` do not appear in the diff, and `extension.ts` gained no line containing `token` or `usage`. The two figures were re-derived from the transcripts by a script that shares no code with the extension: **77.87M and 17.13M** — the same numbers the page showed.

**The turn total is the sum of every API call's whole window, so it measures calls × context, not wall-clock time.** The 77M turn made **286 calls carrying ~271k of context each** in 55 minutes; the 17M turn made **101 calls at ~170k** in 42 minutes. Same hour, 2.8× the calls, 1.6× the context — 4.5× the tokens. Nothing is broken; the second turn was cheaper work.

**And that total is not the subscription quota.** Measured against the live `five_hour` figure on the day: **83% utilization ↔ 20.2M raw transcript tokens** in the window. 98–99% of a total like that is `cache_read`, which the plan bills at a fraction — so reading a quota percentage off the token count, in either direction, gives the wrong answer. The dashboard's plan-usage card reads Anthropic's own numbers and remains the only place that states the quota.

*Fixed on the way:* **a harness `isMeta` line in array form opened a turn on the transcript page.** The string form was skipped; the array form was not, so the page counted one turn more than the session index did, and every turn after it carried the number — and the tokens — of the one before. Measured: 16 such lines across 353 real transcripts.

## 3.59.0 — The backlog (2026-08-03)

A project could say where it was going (**Plan**) and what had happened (**Timeline**), but it had nowhere to keep the hundred small things somebody notices along the way. Those lived in a text file outside the system and were pasted into a chat one at a time — which meant every fix was described twice, and the list itself could not be ordered, filed or filtered. **Faz 4.5** gives a project a backlog.

**‼️ It is a document, not a database.** `Backlog.md` in the project folder, found by `af-role: backlog` like every other project document, and made of lines the vault already understands: the checkbox is the state (`[ ]` open · `[/]` doing · `[x]` done · `[-]` cancelled), `#bug` is the kind, Obsidian Tasks' own 🔺⏫🔼🔽⏬ is the priority, `⛔ P-5.1` is what it waits on. Only *effort* needed a field of its own, and that is Dataview's `[efor:: S]`. So the backlog is editable in Obsidian on a phone, travels in git with the vault, and every line stays inside the user's existing task queries. Nothing new was invented that could be borrowed.

**Every item has a permanent code, and the code is not the order.** `P-5.3` — an area letter, then a dotted path where each level is itself a valid code (`P-5` is a real item, the epic above it). Numbers only ever count up, so a cancelled item's number stays spent and a note from three months ago quoting `K-8` still means that item. Ordering is the **order of the lines in the file**: drag one in Obsidian, or press ▲▼ on the row, and nothing is renumbered. That separation is what makes "do the top five" a sentence you can say without checking anything first. *(ATC codes were the model; the letter/digit alternation was not copied, because `C09AA05` can be written but not dictated.)*

**‼️ Capture costs nothing.** An item may be one line of plain text — no code, no priority, no size. It lands in the `📥` inbox and is filed later by whoever has the context, which may be an agent. `Agent Farm: Add to Backlog` (**Ctrl+Alt+B**) takes a thought from anywhere in VS Code without asking a single follow-up question. A box that asks "which area?" is a form, and the thought that has to wait for a form does not get written down at all.

**`projects.backlog.next` is what "do the top five" runs on.** It drops containers (work lives at the leaves), holds back anything waiting on an unfinished `⛔` item *and says which*, and applies an **effort ceiling that defaults to M** — because "five you can manage" means five that fit in the turn, and without a ceiling an agent picks an XL, leaves it half done and wastes the run. An item nobody has sized is never excluded by that ceiling; a fresh backlog would otherwise answer "nothing to do".

**And the top of it is already in the brief.** Every project session now opens with a `## Next in backlog` section — code, words, badges — so "do the first three" needs no explanation, no paste and no lookup. The rest of the feature is only useful because of this line. The brief's fixed tail grew, so its budget levels grew a floor: at the narrowest width the plan drops to one line while the backlog keeps three, and a project summary is now clipped like every other entry instead of spending the whole budget on itself.

**Nine bridge ops** (`projects.backlog` · `.next` · `.add` · `.check` · `.set` · `.code` · `.move` · `.archive` · `.promote`) and a **Backlog tab** where the row is the editor: the priority and effort badges cycle on click, the checkbox closes the item, and the actions appear on hover rather than walling off two hundred lines with five buttons each. `.promote` moves a work-queue item into a project's backlog — the flow handing over to the stock, one direction only.

Two promises are kept in code and tested: closing a box changes **exactly one character** of the document (no ✅ date is invented — Obsidian's own Tasks plugin writes that when you tick it there), and a **duplicate code or a mismatched parent is reported on the row, never silently corrected**. Archiving moves closed items under a heading at the end of the *same* file, deliberately: a code must never be reissued, and the cheapest guarantee of that is that every code the project ever used is still in the file the generator reads.

*Also fixed on the way: a checkbox inside an HTML comment was being read as a real item, which meant every project created from the shipped template opened with a phantom task — and it reached the brief, where an agent would have gone and done it. Comments are skipped now, like fenced code always was.*

## 3.58.0 — Twelve sessions, one menu (2026-08-03)

Two pieces of Phase 1 that were put aside rather than done. Both are closed.

**‼️ The sessions tables hold a selection now — and it does not get a bar of its own.** A checkbox on every row, **shift-click** for a range in the order you are looking at them, a header box that takes everything *listed* (never the rows a filter is hiding), and a strip that says how many, what they cost and how many are running. The actions are the ones that were already there: the selection rides along on the row's `data-vscode-context`, so the right-click menu that has been the whole session action set since 3.20 becomes a **bulk** menu — pin, label, file to a project, copy ids, interrupt, end, clear — with no new command, no new message, and nothing for a page that embeds the table to answer. A bulk action bar would have been a second, shorter copy of that menu, and the copy is the one that goes out of date.

Three details are the whole difference between this working and this being a trap. A row **outside** the selection carries no selection, so the menu always acts on what you pointed at. A bulk **pin** decides the direction once, from the row you clicked, and moves the whole set that way — toggling each one on its own state would have given back "pin these twelve" with four of them unpinned. And **ending** a set asks first, modally, naming the number; **clearing** does not, because it destroys nothing. The selection is not persisted (a set restored from last week is an action half-taken), and a row that leaves the pool leaves the selection with it.

**The bridge learned the same plural**, because a thing the panel can do to a set and the bridge can only do one at a time is two surfaces drifting apart: `sessions.pin` · `sessions.tag` · `sessions.end` · `sessions.dismiss` all take `sessionIds` now, through one shared helper, and a session named twice is done once. `sessions.pin` **refuses to toggle** a set — it has to be told which way they all go.

**And the old settings-based project model is gone, not deprecated.** `agentFarm.projects`, the one-time import that read it, and the adapter that flattened real projects back into its shape have all been removed. A project is an entity in the registry with a folder of its own; a second definition of the same thing living in `settings.json` is a second answer waiting to disagree with the first. An agent's project is now resolved by the **same** function a session's is, so the portfolio page and the cost table beside it cannot tell you different things about whose job something is. *(If you still had projects only in that setting and never opened the Projects page, they were imported long before this release — the registry has been the source since 3.52.)*

## 3.57.1 — Three ways the write side could still lose something (2026-08-03)

An audit of everything 3.57.0 shipped, looking for the cases where a write that was *supposed* to refuse would instead go through. Three of them were real.

**‼️ A document that could not be read was treated as a document that was not there.** `readProjectDoc` answered `ok: false` for both, and every caller that decides whether a write is safe reads that as "nothing to lose" — so a file held open by a syncing client, or one whose permissions changed, took the *create* path and was replaced. `insertLogEntry` was the worst of them: it caught the failed read, carried on with an empty string, and would have replaced an entire worklog with the single line being added. A read now says **`missing`** only when the file is genuinely absent; the worklog refuses and says why, and `projects.doc.write` refuses to write over a document nobody can see. This is exactly the blind overwrite that op exists to prevent — it just had a door left open behind it.

**‼️ A stale line number could tick the wrong box, silently.** The Plan tab holds each item's line for as long as the page stays open, and the same file is open in Obsidian at the same time — one paragraph inserted there and every number below it points one item down. Ticking the wrong box in somebody's plan is not visible; they find out weeks later. The page now sends the **text it believes is on that line**, and a mismatch is a refusal that says what is there now and to reload. With an 🆔 nothing changes: an id does not move. The check is opt-in, so `plan.check` by line alone still works.

**The people table was unsaved work, and any repaint ate it.** Every payload from the host cleared the editor — and a commit picked up in the background is enough to cause one. Since the editor moved to its own tab with its own Save, that window is as long as the user takes to fill the table. The rows now survive a refresh and are only cleared by switching **project**, where they would belong to somebody else. The page owes the other half of that deal too, so it says **unsaved** next to a Save that is only enabled when there is something to save.

Also: `_AF/` is no longer offered as a place to put a new note — it is rewritten on every session start, so a note filed there is gone by the next spawn.

## 3.57.0 — The project keeps itself (2026-08-03)

**A project's folder was written once and never again.** From the day it was created it had a charter, a plan, a worklog and a deliverables table — and nothing wrote a line into any of them. Not the page, not an agent, not an op. The record only grew when somebody remembered to open Obsidian, which is to say it mostly did not. The project could be read; it could not be *kept*.

**‼️ Ticking a plan item changes exactly one character of your file.** The new **Plan** tab draws the plan document's own checkbox lines as checkboxes, grouped by the headings the file already uses, showing the 📅 and ✅ those lines carry. Ticking one replaces the space inside `[ ]` with an `x`, by offset in the original text. The bullet, the spacing, the indentation, the icons, the Obsidian Tasks metadata (🆔 ⛔ ⏫ 📅) and every line ending in the file come back byte for byte — because rebuilding the line from its parsed pieces would pass the obvious test and quietly normalise a vault, and splitting the file on newlines and rejoining it would turn a one-box request into a whole-file diff in git.

**And it deliberately does not add a ✅ done-date.** Obsidian's Tasks plugin writes one when *you* tick the box *there*. Agent Farm does not write metadata it does not own — so unticking an item that has one leaves it, and **says so** rather than silently deleting a line your own tooling put there. The tab states all of this next to the boxes, because the surprising part is the restraint.

**Decisions are records now, one file each.** `af-role: decision` — found by frontmatter like everything else, so they can be called anything and live anywhere. Appended to a shared document they would be lines nobody can link to, and two agents writing at once would lose one of them. New ones go beside the decisions already there, or into the folder the skeleton declares it `holds: "decisions"` — never into a folder matched by its *name*, which would break the moment a vault called it something else. A title used twice in a day gets a suffix; nothing here can overwrite a record that exists.

**Deliverables go into your table, by your column names.** A row is inserted after the table's last row rather than at the end of the file, and each value lands in the column that names it — so a table whose columns were **reordered** still gets everything in the right place, and one written in another language is filled positionally in the shipped order. A column your table does not have means the value is left out, never pushed into somebody else's.

**Docs is the folder itself.** A tree with each document's `af-role` on it and machine-generated files marked as such, the selected file shown as it is on disk, and **Open** in whichever of the four doc-open modes you already use elsewhere — VS Code, the rendered preview, Obsidian, your own app. The same contract the Notices and Queue boards use, rather than a fifth half-renderer to keep in step with the other four. New notes are created into a folder you pick.

**People moved to its own tab**, because who decides, who pays, who does the work and who you ask is a question *about* the project, not a setting *on* it. It sits next to a link to the project's own People document, and the two are **not** synced: one is structured data Agent Farm injects into every session, the other is your prose about the same people, and rewriting prose from a table is a program editing an essay. *(This also closed a live trap: the people editor used to live on the Settings tab, and the tab's Save posted the whole form — so once it moved, a Save pressed to change a budget would have posted an empty list and deleted every person on the project. It cannot: people are not in that patch at all, and a test says so.)*

**Every write refuses rather than overwriting you.** Read, change, write — with the mtime taken on the read handed to the write, so a save you made in Obsidian in between makes the write **stop** instead of erasing it. Writes land through a temp file and a rename, so a crash cannot leave half a document. Every path a page or an agent supplies is resolved inside the project folder and refused if it climbs out. And `projects.doc.write` will not replace a file that exists unless the caller passes back the `mtimeMs` it got from reading it — a blind overwrite is the one thing that op is built to make impossible.

**The timeline stopped saying it cannot file documents, because it can.** Decisions, deliverables and completed plan items are read out of the project's own folder — their membership is not a guess at all. **But a document event needs a date the document itself states**: a decision's `af-date`, a deliverable's Date column, the ✅ Obsidian wrote when you ticked an item there. A deliverable due "Q3", or an item ticked from Agent Farm, is left **out** rather than stamped with the moment the file happened to be saved — a hundred rows landing at one instant is a timeline that looks precise and says nothing. The page says this, so a missing row reads as a limit rather than a loss. Notices and queue items are still absent and still named.

**The brief got what it was missing — and stopped losing what it had.** It now carries the **open** plan items (not the finished ones; a brief's budget should not be spent on what is already done) and the latest decisions. Growing it exposed a real defect: the system-prompt cap cut the *finished text*, and the brief's **last** section is "Writing back" — where the worklog is, where the plan is, what not to reformat. The most actionable part was the first thing dropped. The injected copy is now built to a **budget that shortens its lists** instead, stepping down until it fits; `_AF/BRIEF.md` on disk stays the full text, which is what the "cut to fit" pointer has always pointed at.

**Bridge — the write side of the project axis:** `projects.doc.list` · `doc.read` · `doc.write` · `log` · `plan` · `plan.add` · `plan.check` · `decision.add` · `deliver` · `people.set`. An agent that finishes a piece of work now records it itself, so the next session's brief is built out of what happened rather than out of what somebody remembered to type.

## 3.55.0 — You can see the project (2026-08-02)

**A project had a page you could only edit.** It knew its name, its folder, its people and its budgets — and it could not tell you a single thing that had happened on it. To find out you left: the Dashboard for the sessions, the Tasks page for the runs, a terminal for the commits, and you reassembled the week in your head. The project was the one thing that knew all four belonged together, and it was the one surface that would not say so.

Every row opens what it is about. A session is **one** row, not a "started" and an "ended" that the reader has to reunite, and it is stamped where it finished, because a list read newest-first should put a three-hour session where it ended. What a session wrote is one row too — one row per file and a single refactor owns the whole day.

A button opens the Dashboard filtered to the project for when the question is how it sits against the whole fleet.

**A project is now marked the same way everywhere.** It has had a colour and an icon since 3.52.0, and the sessions tables — the surface that lists sessions *by project* — were the one place still showing a bare name. Two tooltips there were also still telling you to manage projects in `agentFarm.projects`, a setting that has not existed since that release.

**Measured:** a project with 150 sessions, 3000 turns, 200 tasks, 10 missions and 120 commits builds its whole feed and cost rollup in **42 ms**. `git log` is read per repository behind a 60-second cache and never inline on a repaint, and each tab's data is built only while that tab is the open one.

**Bridge:** `projects.timeline` (the same feed, with `counts` before the filter and `unfiled` naming what cannot be filed yet) · `projects.cost` (the same rollup, caveats included).

## 3.54.1 — The brief was telling the agent the wrong day, and automation was being told the wrong project (2026-08-02)

**A project's dates arrived a day early.** Started and Due are stored as *local* midnight — the page's date picker builds them that way — and the brief printed them through `toISOString()`, which is UTC. Everywhere east of UTC that is the previous day: this machine is at +07, so a project due on 15 August was telling every session it was due on the 14th. The same mismatch was in the project form, and it was worse there, because the form writes back what it displays: the date walked one day earlier **every time the project was saved**. Both sides now build the date from local parts, which is what `templateVars` in the same file was already doing.

**The brief carried two generation times seven hours apart.** Its header stamp is local and its footer was UTC — `(generated 2026-08-02 19:29)` above `_generated 2026-08-02 12:29_`, in one file, leaving the reader to guess. The footer is local now.

**A schedule firing at 03:00 was being told it was working on a project.** The stamp is meant to record the project a task was created under, and for a task a person just made, the window's active project is exactly that. For a task a *timer* made it is not: nobody was looking at the window, and an unattended watch agent was being handed a project's full context and the instruction to record what it did in that project's worklog — about work the project knows nothing about. Schedules (both timed and Run Now, which must produce the same run or it is not a test), triggers and auto-delegated insights now get no project at all; binding a schedule to a project is something to declare on the schedule, not to infer from a window.

**A retry could change projects mid-flight.** `retryTask` copied the attempt, the contract, the CLI, the working directory and the mission — but not the project, so a rerun picked up whatever the window had moved on to, and a retry of a projectless task could quietly acquire one. Retries now keep the original's project, including when the original had none, and a workflow's later steps take the project the *run* started under rather than re-reading the window an hour in.

**`_AF/` no longer dirties the vault.** The brief is rewritten on every single session start, and a project folder normally lives in a git-backed vault — so starting work made the vault dirty and it never came clean. The folder now carries its own `.gitignore` (written once; delete it and it stays deleted, for anyone who does want the brief in git).

## 3.54.0 — Picking a project puts the agent inside it (2026-08-02)

**Until now, choosing a project filed your sessions and nothing else.** The agent still started every conversation knowing nothing: which project, where its documents live, what state it is in, what was done last week — all of it had to be typed, every time, or looked up by the agent at your expense. A project you could see but the agent could not was a label with bookkeeping attached.

**A session started under a project now arrives already knowing it.** Before your first message, it is given the project's name, its documents folder, its code roots, and a generated BRIEF of its current state: status, summary, the people and their roles, **which file holds which role** (charter · plan · worklog · people · deliverables), and the latest worklog entries. Measured end to end against the real CLI: asked "what am I working on and who is the client", a session answers correctly with the user having said nothing at all; asked which file to record its work in, it names the worklog.

It exists despite being absent from `claude --help`'s flag list, which is why the original design had recorded it as unavailable and reached for inline text. The path is quoted, because an unquoted one through a folder called "John Doe" arrives cut at the space.

**The flag is passed again on every spawn, resumes included.** An appended system prompt does **not** survive `--resume` — a session seeded with a fact and resumed without the flag cannot recall it, while re-passing restores it. Both halves are measured, in a test that takes care not to let the seeding turn leak the answer into the conversation history. It is added in the one place each command line is built, so "every spawn" holds by construction rather than by everyone remembering.

**You can read exactly what is being sent.** The channel leaves no trace in the transcript, so a chip sits above the Console composer: `◧ <project> — project context active`, and hovering it shows **the text itself**, verbatim — not a description of it. When no project is set it says so instead of disappearing. Session rows carry the project they were started under. 3.50.0 was titled "the composer stops lying about what it is sending"; sending something on your behalf that you cannot inspect would be that same fault through a quieter channel.

**Cost, measured, not estimated:** a full context — skeleton, people, role map, three worklog entries — is **538 input tokens** (1632 characters; 3.03 chars per token, not the 4 the English rule of thumb assumes). It lands in cache-creation, so every turn after the first re-reads it at a tenth of the price. The brief is capped and cut on a line boundary, with the path to the full text appended, so the system prompt cannot grow without bound as the project does.

**Tasks carry it too — from when they were created, not when they run.** A queued task can start hours later in a window that has moved on to something else; giving it that project's context would be worse than giving it none. Named CLI profiles run a different binary and are left alone.

**Your own rules can ride along.** `agentFarm.projectContextExtra` adds one line of your choosing to every project context — where an installation points its agents at its own conventions. Empty by default: Agent Farm ships general, and what an agent should *do* with a project is yours to say.

**Bridge:** `projects.brief` — the brief, or with `context:true` the exact text a session receives.

## 3.52.0 — A project is a thing now, with a folder, a sidebar and a page (2026-08-02)

**"Project" used to be a name in a settings file.** It grouped agents so cost could be summed per customer, and that was all it could ever do: no page, no folder, no plan, nothing to open. This release turns it into the entity everything else hangs under — while it still owns almost no data of its own, because sessions, tasks, missions, notices and commits keep living exactly where they already lived. The project is the **join** over them.

**Its own sidebar section, directly under Agents.** The tree opens with the **active project** — always visible, even when there is none, because a stamp being applied invisibly is precisely the kind of automation nobody should have to take on trust — and closes with **Unassigned**, which deliberately shows a number that starts out embarrassing. A rule that fails quietly is not a rule.

**Its own page (`◧ Projects`, second in the global nav).** Everything about a project is edited there: name, status, kind, icon and colour, documents folder, code roots, people with their roles, both budgets, dates, tags, and which agents fall to it by default. Nothing has to be typed into `settings.json` any more.

**A folder is part of what a project IS.** Creating one asks where its documents live and builds a starter structure there (charter · plan · people · worklog, plus notes, decisions, deliverables, resources, archive). Nothing that already exists is ever overwritten, so "Recreate" is safe on a folder that was moved and half-restored. If the folder later disappears the project does **not** vanish with it: it stays in the list with a warning and three answers — relink, recreate, ignore — and everything that is not documents (sessions, cost, timeline) keeps working. `agentFarm.projectSkeleton` replaces the shipped layout wholesale, for vaults with their own naming convention.

Rename them, move them into a subfolder, write them in any language — nothing breaks. The same key is what lets a folder **renamed in Obsidian** be recognised as the same project on the next rescan, and a duplicated folder be reported instead of quietly claiming to be the original.

**The rule that made the old model wrong is gone: an agent may work on as many projects as it actually does.** Cost now hangs off the SESSION — the atom that already has a working directory, a time and a dollar figure — and membership resolves in a fixed order: an explicit assignment, then an explicit *no project*, then the longest matching folder root, then the agent rule. Every session still lands in exactly one bucket, so the figures still add up to the fleet total.

Two of those steps are new and neither is decoration. **Longest root wins** fixes a silent misattribution: with `…/miropharm` and `…/miropharm/muvu_talkScribe/ZEN` both declared, first-match handed every ZEN session to the wrong project, and both answers looked plausible. **Explicit "no project"** is a real state: without it, taking a session off a project let the folder and agent rules put it straight back, and the user would never learn why.

**Filing a session is on every session row, everywhere.** One entry on the shared right-click contract reaches all six surfaces that list sessions — Console, Missions, Search, the sessions tables, Live Timeline and Turns — with four outcomes that are genuinely different: file it, move it, take it off (and keep it off), or forget the decision so the rules speak again. Two more sit next to them: **new project from this session** (the fastest backfill there is — the session already knows the folder the work happened in) and **add this session's folder as a code root**, which turns a one-off assignment into a standing rule.

**Migration is automatic and happens once.** The old `agentFarm.projects` setting is imported on first run: agent lists become *rules*, folders become code roots, notes become the one-line summary. No folder is invented — each project asks for one. The marker is set when the setting is seen to hold something, not merely when it is read, because Settings Sync can land after activation and an empty read is not proof of an empty setting.

**Bridge:** `projects.list` · `get` · `create` · `set` · `rename` · `assign` · `current` · `health` · `rescan`. New settings: `agentFarm.projectsRoot`, `agentFarm.projectSkeleton`, `agentFarm.projectStaleDays`.

## 3.50.0 — The composer stops lying about what it is sending, and ctx stops resetting (2026-08-01)

**‼️ The worst bug in the attachment feature was that it kept the files on screen after they had gone.** Attach, send, start typing the next message — and the chips were still sitting there. They were not attached to anything: `send()` had emptied the list, and **nothing ever redrew it**. The chip list was written by hand from three places and never from the render path, so it survived until the shell happened to be rebuilt. Meanwhile the next prompt went out **without** the files it appeared to be carrying. A surface that lies about what it is about to send is worse than one that never had the feature. The list is now a **slot**, drawn by `renderLive` — every keystroke, every data push, every send — and the suite proves it by reproducing the exact reported bug and failing on it.

**A drag repainted the whole page, every frame, for as long as it lasted.** `dragover` fires continuously while the hand is over the page and `dragleave` **bubbles up from every child the pointer crosses**, so turning the outline on in one and off in the other wrote the class dozens of times a second — a style recalculation and a full-page repaint per frame, plus a `getElementById` per frame, for a border that was already drawn. The highlight is now a **state**: it is written only when the answer actually changes, and enter/leave are counted so crossing a child is not a departure. `dropEffect` is set as well, so Windows shows a copy cursor instead of the "no entry" sign. *(This is a real, measured load being removed. It is not proof of what a display driver did during a drag on one machine — nothing here can prove that — but it is the one thing on this side that was hammering the compositor, and it is gone.)*

**Dropping text into the message box works again.** A page-wide drop target that claims *every* drag also claims the ordinary ones: dragging selected text into the composer had quietly stopped working. Files and URI lists are ours; plain text is only ours when it is let go **outside** the box. And a path dragged as text now has to be **absolute** — the old test was "contains a slash", which read every dragged sentence and every URL as a filename and answered each one with a warning about a file that never existed.

**The 📎 dialog showed folders and no files.** `canSelectFiles` and `canSelectFolders` together is not "both" on Windows: there is no such native dialog, so Electron falls back to the **folder** picker — every file vanished from a window whose only purpose was to pick a file, with no type filter row either. It picks files now, with the filters a file dialog is expected to have. A folder is attached by dropping it, and the tooltip says so rather than leaving a dead end at the dialog.

**Every remaining silent ending now speaks**, which is the complaint this feature keeps drawing: a drop whose bytes could not be read, a payload that arrived empty, and more files than the ceiling allows. The ceiling (`ATTACH_LIMITS.count`) is also applied **before** staging and against what is already on the message, so twenty-one dropped files no longer each get written into the temp folder before the twenty-first is refused.

- **A pasted screenshot keeps its suffix, and therefore stays a picture.** A paste often arrives with no name at all, and the suffix is what decides whether the model **sees** the image or is merely told a file exists. The clipboard's media type now travels with the bytes and supplies one. A very long name is shortened from the **middle** for the same reason — a plain `slice()` cut the `.png` off the end.
- **`consolehost.ts` was not a text file.** The filename-sanitising regex had been written with **literal control characters in the source** — a real NUL byte and a 0x1f — so git called the file binary and stopped producing diffs for it. Same rule, written as escapes.
- **‼️ The ctx figure collapsed mid-turn because it was being fed the wrong number.** `system:thinking_tokens` was read as a context estimate. It is not one, and the CLI says so itself: *"Live thinking-token estimate … `estimated_tokens` is the running total for the current thinking block"* (read out of the 2.1.220 binary). It restarts near zero on every block and is emitted constantly — **twelve** of them in one short measured turn — so a session truly holding 225k was repeatedly knocked down to ~100 and shown climbing 100 → 200 → 500 until the next assistant message restored it. It no longer touches the figure. Context is now measured with **`contextAfter()`**, the same function the sessions tables and the session viewer already use, and a zero means "not measured" so the last real figure stands.
- **‼️ And the session's token total was nearly double the truth.** The CLI emits **one line per content block** and repeats the whole message's usage on each of them — a `thinking` line and a `tool_use` line for one reply both carrying `in=10 out=3 cr=15642 cw=6961` (measured, haiku). Every line was counted. On a real transcript that is **55.1M against a true 27.99M — 1.97×** — while the sessions table showed the honest figure for the very same conversation. Each message is now counted once, keyed on the CLI's own `message.id` + `request_id`; one remembered key is enough because the repeats are always consecutive (measured over 403 assistant lines / 194 messages, zero exceptions).

## 3.49.0 — Files go with what you say, and the file decides how it travels (2026-08-01)

**‼️ The Console was meant to be the terminal's equal, and you could not hand it a screenshot.** Everything else had been carried across — steering a running turn, answering an `AskUserQuestion` in place, holding a message back — but the one thing a terminal does with a keystroke, pasting a picture of the thing you are asking about, had no equivalent here at all. Staged drops are swept after a week — that folder is a staging area, not an archive, and nothing else would ever empty it.

- **A held message cannot carry a file, and says so instead of losing it.** The queue keeps strings (`shiftQueued`/`takeQueued`), so parking a message with an image attached would drop the image silently on the way. - **Over the limit is a refusal, never a quiet resize.** 5 MB per image, 20 MB and 20 files per message. A silently downscaled screenshot still gets an answer — a confidently wrong one — so the send is refused by name, and **the message is given back whole**, text and chips together, because the composer clears itself the moment you press Send and a refusal must not cost you what you wrote.
- **The bytes are read at send time, not at attach time.** The composer only ever holds paths, so a 5 MB screenshot is not sitting in webview state — and a file deleted or swapped between attaching and sending is caught at the only moment where saying so is still useful.
- **Attaching to the first message works.** The button renders before a session exists, and `console.start` carries the files into the opening turn — starting a session *with* a screenshot is the normal case, not an edge one.
- **An agent can do it too, in the same commit** (`_REF/agentfarm-dev.md`): `console.send` gains `attach` (absolute paths), resolved through the *same* carrier rule as the button, so a `.png` behaves identically however it arrived. One agent can now hand a screenshot to another agent's session. A refusal comes back as an error, not as a success with a footnote.
- 31 checks added covering the carrier rule against real files on disk (image · text · folder · missing path · uppercase extension), the wire format (image block shape, images ordered before the question, a path written into the sentence in backticks, a screenshot-only message sending no empty text block), what counts as a message at all, the ceilings as one shared definition, and the bridge resolving paths the same way. ## 3.46.1 — The usage 429s, actually fixed: the edge was holding the button's privileges (2026-07-31)

**‼️ 3.45.0 claimed the rate limiting was fixed. It was not, and the reason was in the code that shipped alongside the fix.** The `User-Agent` diagnosis was right and the 60 s beat was applied — but the beat was never the only thing asking. `PlanUsageBar.fleetChanged()` fires on every live hook event, and on each idle/active crossing it called `service.get(true)`: **the button's path.** So an automatic reader, triggered by one of the busiest events in the system, held the *human's* privileges — it skipped the TTL, it skipped the very backoff that had just been added to rescue it, and the only thing left underneath was the 5-second hard floor. Configuring the beat politely was therefore irrelevant, and once limited, the edge kept hammering so the limit never cleared. Measured on the real workload (136 turns in the last hour; a burst of 12 quick turns 10 s apart): **12 requests, 10 s apart → 2 requests, never closer than 60 s.**

- **The three reasons a read happens are now named, because they may skip different things.** `beat` (the timer): skips nothing. `edge` (a turn just ended): skips the TTL only, floored at the user's active interval. `user` (⟳): skips the TTL and the backoff, floored at 5 s. Only `user` is a person; everything else is the extension deciding to spend a request on its own, and it does that on a leash.
- **Only the FALLING edge earns a read.** A turn *ending* is the moment the figures settle at what it cost — and the moment the beat switches to the slow idle window, so without it the settled figure could sit unread for the whole idle interval. A turn *starting* earns nothing: nothing has been spent yet, so the answer is necessarily the one the last read already gave. It was costing a request to learn nothing, and doubling the traffic on the busiest events to do it. (Both directions are still *recorded* — a rising edge that is not tracked turns the next fall into a no-op, and then the one edge that matters never fires.)
- **The edge changes WHEN a read happens, never HOW MANY.** Its floor is the user's own `planUsageActiveRefreshSeconds`, shared with the beat through one `lastFetchAt`: set 60 s and no two automatic reads are ever closer than 60 s, whoever asked for them.
- **An agent's `usage.plan force:true` no longer walks through a backoff either** — it takes the edge path. A looping agent cannot become a request storm, and the op's `describe` says so.
- 18 checks added, including the burst that reproduces the original bug (200 turn boundaries inside one backoff → **zero** requests) and the floor being the user's setting rather than a constant of ours. The old assertion that *asserted* `tick(true)` on the edge — i.e. locked the bug in — is replaced. Suite: **82 files, 3629 checks green.**

## 3.22.0 — The shared constitution reaches the other engines (2026-07-26)

## 2.62.0 — Missions: dynamic multi-agent orchestration (2026-07-17)

## 2.20.0 — Parallel steps & fan-in, wave 3b (2026-07-11)
