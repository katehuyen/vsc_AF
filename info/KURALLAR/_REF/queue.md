# Work Queue — the User→Agent Async Channel (mirror of Notices)

**Notices is agent→user; the Work Queue is user→agent.** While using the system the user drops the fixes they notice — small or large — into the queue **without friction** (no separate turn for each); items **do not disappear until they are handled**. Bridge ops in Agent Farm: `queue.*` (add/list/get/edit/group/delegate/stamp/setUrgency/pin/archive/remove/fromNotice); in the UI two tabs, `🔔 Notices | 📥 Queue`, plus the `Agent Farm: Add to Queue` command (Ctrl+Alt+Q). **The extension UI is English.** **Verify the schema with `farm.ops`.**

**Pipeline (state machine):** `captured → grouped → delegated → done` (+ `blocked` = a question for the user, the only attention-grabbing state; `dropped` = invalid). `done`/`dropped` are terminal; a non-terminal item **cannot be deleted** (even if the user says "delete it" — a bad entry is moved to `dropped`, which counts as handled).

**The engine is manager.** It scans the queue, groups similar items with `queue.group`, and once a group **matures** delegates it to the right agent **in a single turn** (linking via `queue.delegate`), then supervises with "delegate but own it" and stamps the result with `queue.stamp`. Engine details live in manager's `DUTIES.md` and `CLAUDE.md`.

**‼️ An item can say WHO should take it.** Three optional axes beside `target`: `engine` · `model` · `effort` — given at capture (`queue.add`), changed later with `queue.route` (each axis moves on its own; `""` clears one), and filtered on in `queue.list`. **An empty axis is a real answer** — *the item does not care* — so "do the work meant for me, and the work nobody claimed, and leave the rest" is **two** calls: `engine:"<yours>"` then `engine:"(none)"`. Omitting an axis is a THIRD thing: every item, claimed or not. **Nothing is dispatched from a route** — the queue does not start work; the route is what a task prompt reads to pick its own share out of the pile.

**‼️ Start every sweep with `queue.maturity`.** It applies the thresholds for you and returns `{actionable, reason, ripe[], ungrouped, starving[]}`. **`starving` is the one `queue.groups` cannot show you:** an item that was never grouped has no `groupId`, so a sweep reading only the group digest sees an empty list while a user's own answer rots past the age ceiling — which is exactly how a captured entry sat unprocessed until it was found by hand. Never conclude "the queue is idle" from `queue.groups` alone.

**Answer ≠ Report (user rule):** An explanation of *"what was done"* is an **answer**. If short, use `queue.stamp resolution=` (inline); if it needs detail, use `answer=` (full markdown → **`00_OUTPUT/01_CEVAPLAR`**, with an archive counterpart — **not a report**). A **report** happens only when the user's input explicitly says "give me a report" → `reportPath` (`10_REPORT`, the normal report flow). The *product* of an instruction (image / file / report) and the *answer* to the work are two different things.

**Notices ↔ Queue cross-linking:** The user can turn a notice into a queue item with one click (`queue.fromNotice`; by default the message is removed, otherwise a link is written into the notice's `spawnedItems`); answering a `question` also creates a queue item **automatically**. An item links back to its source via `sourceNoticeId` and **carries the notice itself**: `sourceNoticeTitle` · `sourceNoticeAgent` · `sourceNoticeType` · `sourceNoticeBody` · `sourceNoticeSections` · `sourceNoticeReportPath`, plus the notice's `projectId`; `target` = the notice's agent when that is a real agent (a notice raised by Agent Farm itself stays unrouted). **Such an item is owned by the agent whose notice it came from** — it finds it with `queue.list { sourceNoticeAgent:"<me>", active:true }`, acts, and stamps it; manager's sweep leaves it to that agent unless it is past the age ceiling. The status-bar bell counts notices-unread and queue-blocked **together** (a single attention indicator).
