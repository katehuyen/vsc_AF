# Vault Writing Rules

**Read this BEFORE writing.**

- **File naming:** `K-CAT - Free Name - … - YYMMDD.md` → K: quality (A=highest, E=lowest), CAT: category code (REF/KNO/INF/SRC/DAT/DOC/SOL/SOP/PLN/PRD/IDE/DRF/OBS/LOG/COM/TMP/MAT/RAW/TEM/ARC/OTH — choose via the decision tree; REF is not the default). **CRITICAL: digits are for FOLDERS only; never prefix a filename with `00_`/`20_`** (file = `K-CAT - Name`, folder = `NN_Name`). This rule binds **the agent building the system too** — including system-definition files. Full definition + decision tree: `70_REFERENCES/11_Obsidian/01_System/A-REF - Dosya Adı Sistemi.md` · in-system copy: `00_AGENT_AREA/99_SYSTEM/A-REF - Dosya Adı Sistemi (Vault Kuralı - Kopya).md`. The name must contain **the keywords someone would search for**. Check this pattern before writing; do not skip it.
- **Placement:** **Every layer** of the path hierarchy must match the content, not just the last folder. Under `45_AI` = content whose subject is AI; `NN_Projects` is project-specific (no general knowledge); general computing/internet knowledge → `60_COMPUTER`. Project folders (`10_PROJECTS/`): root is strictly reserved for the 6 core role files (`Charter.md`, `Plan.md`...); all other project documents go into `10_Notes/` or designated subfolders (`_REF/project-session.md`). **Look for an existing home first**; if one exists, use it — do not open a new one. Dropping it into the first folder that comes to mind is forbidden — find the most correct place relative to the whole vault tree.
- **Turkish character sensitivity:** Turkish characters in file/folder names (dotted İ etc.) are preserved — otherwise search and read calls 404.
- **Heading-target trap:** When targeting a heading with `vault_patch`/`vault_read`, if that heading is nested under an H1 you must give the **full `H1::H2` path** (get it from `vault_get_document_map`) — passing only the H2 text makes the tool fail to match and **silently time out instead of erroring**. If you get stuck, do not blindly retry: check the document map and use the correct full path.
- **Vault self-containment:** Tools built for the vault (plugins etc.) must live entirely inside the vault, with no external dependencies, and be git-portable (pull + Obsidian on another machine is enough). Files scattered across the system plus an uncontrolled/crude flow = rejected.
- **‼️ Mandatory: Write/modify through the Obsidian MCP or Local REST API, never with raw disk writes/shell.** Obsidian holds open file handles and keeps an in-memory index. Direct disk modifications (PowerShell `Set-Content`, mass `fs.unlink/writeFileSync`) cause 0-byte truncation on open files, choke Obsidian's background file watcher (`fs.watch`), and freeze/delay UI indexing.
  - **Single / small changes (1–5 files):** Call Obsidian MCP tools directly (`obsidian_put_content`, `obsidian_patch_content`, `obsidian_delete_file`).
  - **Large batch operations (10+ files):** To minimize tool-call token overhead without desyncing the UI, write a batch script that sends HTTP requests to the running Obsidian Local REST API endpoint (`http://127.0.0.1:27123/vault/...`) instead of writing raw files to disk. This immediately commits changes to Obsidian's live memory tree with zero file-locking or indexing lag.
  - **Provenance frontmatter:** When filing notes from `01_YERLEŞTİR` or other inboxes, always include a standard provenance frontmatter block (`source_date`, `placed_by`, `original_name`, `tags`) at the top of the file so the origin is never lost.
